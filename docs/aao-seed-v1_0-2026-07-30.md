What was ruled 30 July, by Matthew

* Build starts in the sandbox now. The old ordering ("Apex only after Gate 1 passes") is amended to parallel tracks: schema and deterministic plumbing (objects, triggers, span verification, journal/mirror, replay) build immediately in `altify--aossb2`; anything a charter writes stays governed by Gate 1's bar, and no model-written verdict is trusted until test round two clears. Production remains read-only, unconditionally.
* Prefix `AAO_` on all API names. Standing note: the endgame is a 2GP sharing the `ALTF` namespace so our Apex can call Altify's non-global classes directly; AAO-now is the prove-it-first choice and a later rename/redeploy is the accepted cost. Record this wherever naming is discussed so nobody optimizes against it.
* Spans and element lists are JSON long-text fields on Candidate / Evidence Contract / Claim, plus a direct Source lookup on Claim so "which claims rest on this transcript" stays queryable. Nuance to keep honest: receipts stream to Data 360 as individual rows, so claim-grain analysis is on the plane from day one; span-grain rows exist only if a per-span stream shape is chosen later — routing choice, never a schema migration.
* The mirror holds only TRUE / FALSE / UNVERIFIED. Abstention and not-addressed write no Claim. Every abstention persists as a Candidate row with enum reason (`model_missed` / `nobody_said`) — the abstention-rate detector is Candidate analysis by charter version. Optional cheap visibility: two counters on Roll-Up.
* Open design item, named, not settled: per-org charter overlay — injectable natural-language sections in charters for orgs whose ontology drifts from what charters read. Rule-data family, sibling of Evidence Contract. Do not improvise it mid-build; surface it as its own decision when charter config is designed.
