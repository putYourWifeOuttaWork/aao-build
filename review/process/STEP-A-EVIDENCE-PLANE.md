## THE TWO STRUCTURAL THINGS (a) HAD TO SOLVE

### 1 · THE MEANING MAP WAS KEYED BY CODE, AND THAT BREAKS LAW #1

`AAO_LocateCharter.MEANINGS` maps a contract CODE to what it may voice, and a contract absent from
it **has every pair parsed away and read as silence** - the forty-seventh stamp's finding, which
cost an entirely empty Problems harvest to learn.

That works only because those seventeen codes are ours. **A DISCOVERED rubric carries the
customer's codes.** So every contract discovery mints in a real org would have been mute, in every
install, permanently - and it would look exactly like a model that found nothing.

**The fix is family-level, and it is a property of the family rather than a workaround.** An
assessment question is an INVERSION LAW: the affirmative is what the deal needs, so the contract IS
the question and the only thing left to say is which way the words went.

```
AFFIRMED - the words establish the condition the deal needs
DENIED   - the words establish its negative; a VOICED NO is an establishment in its own right
```

Uniform across every question in the family, in any org, whatever the customer called it.
Never-established stays SILENCE - no pair, no row - and the by-stage marker decides when that
silence becomes a flag. Verified from the runtime: **36 declared contracts, 0 mute.**

### 2 · THE RUBRIC VERSION DID NOT NEED TO MOVE, and I checked before assuming it did

`AAO_RecallGate.declaredSet` selects on `AAO_PassContracts.RUBRIC_VERSION`, so a contract minted
anywhere else never reaches the reads. **That is why `AAO_Discovery`'s six live contracts at
`discovered-v1` have never ridden the §P8 pass at all** - discovery's output has been invisible to
the live pass since §P8 existed.

Minting Process into the same generation raised the watermark question: does adding fifteen
contracts to the declared set have to move the version? **No, because the provenance law is already
satisfied elsewhere.** `AAO_LocateCharter.effectiveVersion` composes the charter's version with a
fingerprint of the declared set's contract keys - *"an edit anywhere in either half moves the
string, and it cannot not move."* Fifteen contracts entering the set therefore move every stamped
row's provenance automatically, and bumping `RUBRIC_VERSION` would supersede twenty-one live People
contracts to record something already recorded.

**What is left is a misleading NAME, not a broken mechanism:** the string reads `people-p8-v1` and
now covers Process too. Named rather than fixed, because renaming a version string is exactly the
kind of change that looks cosmetic and rewrites provenance.
